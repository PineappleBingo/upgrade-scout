# 사람 접점 지도

사람이 보고·고르고·승인·거절·내려받는 자리는 **라벨이 생기는 자리**다. 학습 루프·Jev 보정은 여기서 나온 라벨로만 잴 수 있다.

## T-id 표 형식

| id | 누가 | 행동 | 화면·라우트 | 남는 데이터 | 버려지는 데이터 | 읽는 쪽 |
|---|---|---|---|---|---|---|
| T01 | 사용자 | pick | `build-panel.tsx:337` · `POST /api/builds/[id]/answers` | `Feedback answer`(before=추천, after=선택) | 미리 골라져 있던 값 | `recommendation.ts` |

행동: view · edit · pick · approve · reject · download · upload · configure.

## 보는 순서

1. UI 버튼·폼 → 라우트 핸들러 → 저장하는 테이블까지 따라간다(파일:줄).
2. **버려지는 데이터**를 찾는다 — 저장하지 않는 선택, 쓰기만 하고 아무도 안 읽는 원장 종류(write-only), 화면에만 있는 상태.
3. 사람 라벨이 모델 제안에 끌려갔는지(앵커링) 알 수 있는지 본다 — 미리 선택된 값이 기록되는가.
4. 각 접점을 판단 지점(JP)과 잇는다 — 이 라벨로 어떤 Jev 질문을 보정할 수 있나.

## 흔한 발견

- 쓰기만 하는 원장 종류 → 읽는 쪽 만들기가 가장 싼 업그레이드인 경우가 많다
- 저장 안 되는 “다시 시작”·“재실행” → 암묵적 거절 신호를 잃는다
- 수동 SQL로만 하는 표시(골든 등) → UI 한 줄로 라벨이 늘어난다
