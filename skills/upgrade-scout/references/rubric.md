# 채점 루브릭

**합계·등급·판정은 스크립트가 낸다**(`scripts/score-table.mjs`). 에이전트와 메인은 축별 점수만 매긴다.

## 1. 시너지 (메인 순위) — 적합 40 · 비용 30 · 리스크 30

각 축 0–10, 높을수록 좋음. 이전 실행(ST · ANF · TVSE, 모두 작성자 프로젝트)과 비교할 수 있게 가중치를 유지한다.

| 축 | 0 | 5 | 10 |
|---|---|---|---|
| 적합 | 대상의 필요와 무관 | 한 부분을 도움 | 필요를 그대로 덮음 |
| 비용 | 새 런타임·대규모 재작성 | 모듈 하나 추가 | 설정·복사로 끝 |
| 리스크 | 라이선스·보안·약관 문제 | 조건부(키·외부 전송) | 로컬·MIT·끌 수 있음 |

**근거 등급**: A = 구현을 코드로 다시 확인 · B = file:line이나 공식 문서(재확인 전) · C = README 주장·2차 자료.

**상한**
- 강제 제약(K, hard) 위반 → 합계 3, 제외 목록으로
- 근거가 주장뿐(C) → 합계 6, 상위 5에 넣으려면 “검증 필요” 태그
- 자체 주장 성능·목표 수치는 인용만, 점수에 반영하지 않는다

**언어 계수**(선택, 항목의 `lang`): 후보의 값이 모델 정확도에 달렸는데 그 수치를 다른 언어에서 쟀다면 0 초과 1 이하를 곱한다(상한보다 먼저). 언어별 감사 수치가 있을 때만 — 예: 한국어 state는 같은 문항에서 정확도 −6.5pp(jujumilk3/jev-calibration-audit, 저자 자체 수치) → 0.935. 출처는 `lang_ref`에. 감사가 없으면 1과 “언어 감사 미확인”.

**이중 채점**: 블라인드 채점과 축별 차 ≥2면 재확인(`references/orchestration.md`).

## 2. J-루브릭 — Jev 적합도 (0–100)

각 기준 0–2, 가중 합 100. **관문이 합계보다 먼저**: J1 = 0 → reject, J3 = 0 → code(코드에 남김). 그다음 ≥70 high · 50–69 mid · <50 low.

| # | 기준 | 가중 | 2점이 뜻하는 것 |
|---|---|---|---|
| J1 | 답 공간이 닫혀 있다 (관문: 0이면 거절) | 14 | 선택지 ≤255 · 단계 2–10 · 예/아니오 |
| J2 | 지금 LLM이 JSON 라벨·점수만 돌려주는 자리 | 10 | 대체할 LLM 호출이 있다 |
| J3 | 산술이 아닌 의미 판단 (관문: 0이면 코드) | 12 | 셈·날짜·수 비교·정확 조회가 아님 |
| J4 | 반복된다 | 8 | 요소·세그먼트·턴마다 |
| J5 | 지연·비용 압력 | 8 | 사람이 기다리거나 양이 많다 |
| J6 | 짧은 영어 state | 10 | 이미 영어·≤6k자·번역 LLM 불필요 |
| J7 | 해당 없음·폴백 | 8 | none·unclear를 둘 수 있다 |
| J8 | 틀려도 회복·게이트 | 10 | 사람·게이트가 받아 준다 |
| J9 | 보정 데이터 | 6 | 사람 라벨 ≥30이 지금 있다 |
| J10 | 적대적 텍스트 노출이 낮다 | 4 | 외부 글이 state에 거의 없다 |
| J11 | 기존 게이트에 맞고 스위치로 끈다 | 6 | |
| J12 | KPI를 잴 수 있다 | 4 | |

`node scripts/score-table.mjs jp.json --mode jev --format md`

**분류 용어(capability-analyst `triage`)**: DIRECT(그대로) · NEEDS_SHAPING(질문 나누기·영어 버킷·no-match 추가가 먼저) · NOT_FOR_JEV(셈·날짜·생성·정확 조회·사람만 할 판단). J 판정과의 대응은 대체로 high → DIRECT, mid → NEEDS_SHAPING, code·reject → NOT_FOR_JEV지만, 합계가 아니라 이유로 적는다.

**J-점수는 시너지 합계에 섞지 않는다** — 옆 열로만.

## 3. 플러그인·스킬 매트릭스

각 0–10: 필요 적합 ×3 · 근거 ×2 · 보안 ×2 · 유지 ×1 · 토큰 ×1 · 중복 ×1 → 합 ÷ 10.

| 판정 | 뜻 |
|---|---|
| adopt | 채택(설치는 사용자 동의 후) |
| trial | 조건을 걸고 시험(버전 고정·샌드박스·손으로만 실행 등) |
| assess | 아이디어·방법만 검토 |
| hold | 보류 |

관문: 라이선스 불명 → assess 이하 · `claude plugin validate` 오류 → 설치 금지 · 훅·MCP가 있으면 보안 메모 필수 · 훅이 프로젝트 스크립트 실행/전역 설정 쓰기/주입 문구 → hold에서 시작 · plugin.json과 marketplace.json 발행자 불일치 → hold.

## 4. Jev 보조 점수 (선택)

`packs/jev/qsets/scorer-questions.v1.json`의 `fit`(0–4 기대값) × 2.5 → 0–10 “보조” 열. 없으면 “—(미실행: 사유)”, 절대 0으로 채우지 않는다. 메인 적합과 차 ≥2.5 · confidence ≥0.6이면 재확인 대기열. 같은 요약을 읽는 모델이라 **확증으로 세지 않는다**.
