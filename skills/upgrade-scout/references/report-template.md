본 산출물은 **HTML Artifact**다 — 산문은 사용자가 요청한 언어, 기본 한국어. 쓰기 전에 artifact-design(또는 Artifact quickstart의 페이지 가이드), 순위 그림 전에 dataviz, 흐름 그림 전에 artifact-diagramming을 로드한다(세션에 있는 것만). 셸은 `assets/report.html`.

2. 00 결론: KPI 6 · 판정 카드 5–7 · 시너지 순위 그림(`score-table --format html`)
3. 01 대상 분석: 파이프라인 그림 + 인벤토리 표(근거 열) + 레퍼런스 판별 결과 표(유형 · 켜질 팩 · ask, `refs.mjs classify` 결과)
4. 02 가정 검증: present/partial/absent + 검색 범위
5. 03 레퍼런스 유형별 장 — 리포: 후보 리포(분류별 표 — 가져올 것 · 안 가져올 것 · 연결 · 적·비·리 · 시너지 · 근거 등급) / 설계 문서: 원문 요약 · 대응표(있음/부분/없음) · 빠진 조각 · 충돌 / 모델 능력: 능력 시트 · 판단 지점 지도 · 실측(팩이 켜졌으면 질문셋 · 게이트 · 보정도) / 생태계: 최신 사례 표
6. 04 렌즈 장(`LENSES`에 있을 때만) — 에이전트 아키텍처: 조직도 · 에이전트 표 · 원칙 갭 표 · 쪼개기/합치기 / 자기개선: 체크리스트 표

9. 07 UI/UX(`LENSES`에 ui가 있을 때)
10. 08 제외: ❌ · ⚠️
11. 09 로드맵 · 결정 질문 · 병렬 가능한 P0 표시
12. 10 재확인 로그 · 수리 로그 · 블라인드 차 · 팩 지식 갱신(켜진 팩이 있을 때) · 실행 메타(에이전트 수·실패·축소·버린 것) · 다음 실행 메모 · 출처 · 재리서치 프롬프트

## 템플릿 B — Jev 통합

TL;DR(판정별 수) → 판단 지점 지도 → 결정 매트릭스(J1–J12, 0·5·10 표시, 합계·판정은 스크립트) → 통합 설계(판단 레이어·원장·스위치) → 질문셋 v1 + state 규약 → 보정·평가 계획(오프라인 dry-run 기본, `--spend`/`--live`는 동의 후) → 약점 체크리스트 → 사례 근거(증거 수준 표시) → 수리 로그 → 실행 계획 → 재리서치 프롬프트 → 출처 + 레지스트리 스냅샷.

## 그림·표 규칙 (실제 발행에서 확인한 것)

- 흐름 그림은 viewBox 너비 900 안팎, 제목 13px·부제 11px. 상자 종류: 기존 `.sv-box` · 새 코드 `.sv-new` · Jev 판정 `.sv-jev`(점선) · 사람 `.sv-human`. 화살표는 polygon, 색은 토큰.
- 글자 폭을 추정해 상자를 넘치면 문구를 줄인다(한글 1자 ≈ 글자 크기, 라틴 ≈ 0.56배).
- 넓은 표는 `.tbl` 안에서만 가로 스크롤. `table-layout: fixed` + `colgroup`으로 열 폭을 정하고, 숫자 첫 열은 좁게.
- 목록이 긴 원본(101개 등)은 `<details>` 안에 둔다.
- 휴대폰 폭(390px)에서 페이지 자체 가로 스크롤이 없어야 한다 — Playwright로 `scrollWidth`를 확인.
- 색만으로 뜻을 전하지 않는다 — 점수는 숫자를 같이, 판정은 글자 칩으로.
- 모델 의견(Jev·LLM 점수)과 코드가 센 숫자는 다른 열·배지.
